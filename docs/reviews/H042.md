The path includes the Settings action, Tauri command, engine reservation, lifecycle, file preparation, NSIS registration, recovery, and reopen. The scope is one user's installation. The application version changes with the same engine and data format.

Before replacing a file, the app checks its size and SHA-256 again through an open handle. It compares the installation directory with the existing NSIS registration and running EXE. It prepares the new file in the target's directory. A source change or target lock makes the operation return an error. It keeps the previous EXE in a separate recovery file. Rollback changes the application file and the registered application version.

The app checks pending settings and report operations before it accepts exit.

The UI waits for a verified candidate and a stopped engine. The user confirms installation or rollback in a separate action. A development build does not offer installation authority. The app translates fixed error codes. The UI does not execute content from a file path or from downloaded HTML.
