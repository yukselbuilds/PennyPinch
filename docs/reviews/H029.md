# H029 — Disconnect acceptance review

6 November 2026. The lead agent owned config ownership, routing, streams, and acceptance. The existing Luna xhigh worker wrote only the confirmation UI. The lead took over after the worker completed and stopped. The work used the same worker, model, and global settings. Development savings and time remained unmeasured.

Remove now requests confirmation. The dialog shows the client, the scope, and whether the client may need to reopen. Successful native Undo reverts only the routing fields the app owns. The engine and other clients stay open. This work also fixed missing tokenizer data and incorrect graceful shutdown classification found during acceptance of Stop with active SSE.

The review assumed one desktop user and a limit of 32 active TCP connections through the relay. It used the short transport fixture with three requests. Sustained load at 32 connections remained untested.

## Critical source paths

- `Applications` opens `ConnectDialog` and then `DisconnectDialog`. The confirmation uses the same `connectionActionClient.undo` call. The handler in `main.rs` runs `PlanManager.undo_connection` in a blocking task. It uses `undo_owned_endpoint` in the atomic config and ownership transaction. The existing writer checks the owner, revision, fingerprint, canonical target, and scope. Undo preserves conflicts.

  Success requires an acknowledgement that ownership was released. An unknown state or a conflict requires a fresh read.
- Remove leaves the engine running. Stop follows a separate path. RuntimeManager starts draining stable ingress, then stops the engine through the pinned controller and helper. The relay drains within its budget. The manager checks the owned port, process, Job, and reader. The change adds no direct-upstream fallback or POST replay for new clients.
- The review checked tokenizer asset URLs and checksums against the pinned tiktoken source. The preparation script downloads public data and reuses a verified cache. The script runs no downloaded code. It checks 6 assets and 7 offline encodings. The helper sets the cache path only in its own engine environment. The update set the Rust pins for the controller and helper programmatically. Vendor files stayed unchanged.
- `BoundedEngineOutput` keeps only the fixed drain timeout flag for this case. The review verified the cancellation marker in the pinned Uvicorn source. Exit code 0 and the lifespan marker alone no longer qualify as graceful shutdown. The DTO schema and existing shutdown budgets still apply.

The fixture explicitly set the accepted socket mode on Windows. A WouldBlock result on the first nonblocking read does not prove closure. The review rejected an added limit of 2 seconds for the private listener because the product gate has a different timing contract. The app makes no guarantee that the private port closes within 2 seconds.

The stable ingress defines the user boundary. The test verified that a new request closed before receiving response bytes. The existing SSE connection stayed open. Final cleanup completed within the existing shutdown budgets.

**Decision. The review accepted local H029 and found no blockers.** The evidence matched the final candidate fingerprints. Only the test fixture changed, so the team reused the Node and build checks. It refreshed the relevant Rust gate. [Evidence](../proofs/safe-disconnect.md)
