# H028 — Safe pause review

5 November 2026. Pause stops compression of new content at request or frame boundaries in the app-owned engine. The same engine retains content it already sent and its CCR data. The main button offers Start, Pause, or Resume. A separate action in details stops the engine. [Evidence](../proofs/safe-pause.md)

The lead agent traced the renderer through the strict client and Tauri command to the runtime actor. The review covered compare-and-swap (CAS), the exact owned peer, the private acknowledgement, and engine config and replay. It checked startup pins, health recovery, the source guard, and callers in error and shutdown paths.

The review assumed one local user and concurrent coding requests. Sustained performance and resident set size (RSS) remained unmeasured. The lead fixed four issues before acceptance.

1. The pinned Anthropic path skipped cached-prefix replay with `optimize=False`. The fix in `runtime/optimization_control.py:261` keeps the previously sent prefix stable on later requests after Pause. Responses uses a separate adapter for its records and prefix. A multi-turn replay with the real engine verified the behavior.
2. A thread could prepare a result after a timeout or cancellation in the vendor call. The fix in `runtime/optimization_control.py:306` lowers replay trust in that case. A late result gives no evidence that the engine sent the prefix. A paused request fails closed if replay trust is lost. The 11 unit tests and the SSE and WebSocket runs with the real engine covered this boundary.
3. A matching visible body could be confused across routes if the scope hash omitted effective routing inputs. The fix in `runtime/optimization_control.py:202` includes the header pair `x-headroom-base-url/original-path` and the request path. It also uses the auth value Starlette selects first when headers repeat. The route separation test passed. The record excludes secrets.
4. The previous control could display a known state after both the acknowledgement and read failed. The fix in `src/App.tsx:297` marks the local state unknown until a fresh read restores it. While the action is pending, the app blocks navigation, Connect, and a second lifecycle action. The full-app fixture showed no early success or second command.

The control client sends one private POST. It verifies the peer PID, held Job, and generation before it sends the secret. Readiness data includes the token only in the private record. Debug output redacts it.

The control applies to the engine the app owns. Client config, model, reasoning, authentication, and management of a second engine stayed outside the change. Active streams have no new retry or failover path. Replay storage has limits. Metrics keep private replay bookkeeping out of provider cache-hit data. The change removed unused Overview control text and used existing dependencies.

The local gate passed 138 frontend tests and 349 Rust tests. It ignored 6 opt-in tests. The actual manager test and Python controller tests also passed. The native controls and isolated UI fixture covered keyboard input, unknown and pending states, narrow views, and scaling. The owned app exited with code 0.

The first native fixture expected a `status` field in the ingress snapshot. The wire contract has no such field. The team fixed only the test selector and contract check. It reused the product gate.

The single Luna worker prepared the presentation, limited Python tests, and isolated UI fixture. The lead agent confirmed that the worker stopped and took over. The lead owned the engine and native implementation, the connected review, and acceptance. After syncing CodeGraph, the lead matched a narrow `set_optimization` query to two native symbols. The query served as source discovery.

**Decision. The review accepted the local H011/H028 scope and found no blockers.** Live providers, full model features, other operating systems, installation, and sustained load needed separate verification. Model and agent support needed their own evidence. Development savings remained unmeasured.
