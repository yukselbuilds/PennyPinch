# H030 — Tray and shutdown review

7 November 2026. The lead agent completed code review, the local gate, and native acceptance. The lead closed H030. H031 had yet to start.

If a native tray is available, a window-close request hides the window. Full exit requires nonce confirmation. The exiting process holds the client config writer in a terminal state. The existing shutdown sequence stops the verifier, collector, owned runtime, and tray, in that order.

Config undo, bypass, authentication, model and reasoning settings, and automatic startup stayed outside this change. The review assumed one user and one local app process.

The lead traced the connected path `App → DesktopLifecycle → desktop-events → main.rs commands → Lifecycle/PlanManager → ExitGate → OverviewManager/RuntimeManager/TrayController`. The review included the native `CloseRequested` event and tray menu. It checked `get_runtime_snapshot`, `set_optimization`, `save_preferences`, the config PreviewGuard callers, and the H029 shutdown contract.

The single Luna xhigh worker wrote the UI and test slice. The lead reviewed the source and critical paths after the worker completed. Duration and development token savings remained unmeasured.

## Findings fixed during review

| Before | After | Why |
| --- | --- | --- |
| Tauri lacked event permission, so the first UI read did not occur. | Only the `main` capability gained `allow-listen` and `allow-unlisten`. The native UI received the real tray state. | The frontend receives the backend event. Native errors remain visible. |
| Tray projection expected `compression.can_pause`, which the DTO lacks. | It reads `capabilities.pause` and the compression status, generation, and revision. The unit fixture matches the real DTO. | Pause remains available when the engine is running. The compare-and-swap check still rejects stale actions. |
| In the narrow layout, the exit dialog was inside a hidden sidebar ancestor. | The dialog uses a portal in the body. The native narrow view shows Exit in the footer. | The user can reach the exit controls. |
| After StrictMode cleanup, an old async subscription could read the disposed ref from the next effect. | Each effect uses its own cancellation guard. The fixture checks that one subscription stays active. | The guard prevents duplicate notifications and lingering subscriptions. |
| The TypeScript error decoder built a free-form string template. | It derives `message_key` from a validated union code. | The full build checks the actual TypeScript types. |

A native action uses the acknowledged generation and revision on the screen. A stale menu action cannot reverse the operation. Unknown state does not mean ready. Cancel, a stale token, or busy state starts no shutdown or config write. Confirmation and the config hold occur in the same critical section.

After the existing shutdown sequence, the app waits for a bounded time for any runtime or tray action already in progress. It manages only its own processes and ports. Hiding the window keeps an active stream open.

The gate passed 146 frontend tests and 356 Rust tests. It ignored 7 opt-in tests. Formatting, TypeScript checks, and Vite and native builds passed.

An isolated component fixture tested Turkish and English, light and dark themes, a narrow layout, the portal, focus, Escape, and Tab. It checked parent busy state, duplicate actions while a request was pending, and recovery from stale errors. Native and provider behavior had their own scope. The review found no open correctness or security issues. Native tests verified normal drain with exit code 0 and a stuck stream with exit code 1. They also verified engine loss and Escape, Tab, and Enter in Sky. The 43 checks matched the relevant sources and artifacts.

The user reported completing Start, X, Open from the tray, Pause, and Resume. The lead independently checked the final open window. It showed the engine On and Pause enabled. The user provided the evidence for the menu clicks.

`manual-final.json` and `closeout.json` record matching source, binary, distribution, tool, operating system, and Python fingerprints. The team reused the product gate for documentation closeout. H030 passed local acceptance at 29/51. Work stopped at the end of this task.
