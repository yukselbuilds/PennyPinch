## Paths reviewed

The review traced H023 `normalize` and `project_headroom_041` to `MetricsStore::ingest_projection`. The store checks the input and slot. It uses existing directory pins and checks the file for hardlinks and reparse points. It merges and upserts events in a SQLite transaction. It filters by the local calendar and retention. It calculates weighted totals within groups with the same basis.

The renderer can query the store only through `get_metrics_summary`. The asynchronous native handler separates blocking database work. Setup holds the monitoring identity in a clone of the same store. H025 still needed the collector and UI connection. The task list and contracts record that scope.

Writes preserve existing authentication, model, route, and ownership settings. SQLite receives bounded metadata through parameterized SQL. The store rejects a foreign schema and preserves its data. An empty query creates no files.

The review checked the database header and transaction. It also verified a real reopen in a separate process. The H023 comparability criteria stayed the same.

## Findings fixed

- A query for 65 different tokenizer groups could return an unbounded native response (`src-tauri/src/metrics/query.rs:103`). The fix caps the response at 64 groups and reports `omitted_basis_groups`. The combined percentage for mixed bases stays null. The regression failed first and passed after the fix.
- A nil UUID in URN form could pass parsing and escape the plain-text nil check (`src-tauri/src/metrics/store.rs:304`). The new validation requires a canonical, non-nil UUID. The error response excludes the invalid input. The regression failed first and passed after the fix.
- A new valid hexadecimal `event_id` could create a second row for the same origin and slot (`src-tauri/src/metrics/normalize.rs:363`). The store now checks each non-conflicting `event_id` against the origin and slot hash. A duplicate cannot inflate the total. The regression failed first and passed after the fix.

BTreeMap groups records by basis and component and avoids an O(n²) group search. The review stayed within its product scope and avoided cosmetic refactors. It reused the existing directory-pin helper. The design uses one store and avoids rewriting a complete JSON history on each poll.
