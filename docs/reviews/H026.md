# H026 — ana ajan kabul incelemesi

5 Kasım 2026. Ponytail-review ve kalite incelemesi birlikte yürütüldü. Beklenen kullanım tek masaüstü kullanıcısı, H024'ün100.000 event/128MiB sınırları ve H025'in5 saniyelik örneklemesidir; bu yükte performans ölçülmedi. Depo bütünü yeniden audit edilmedi.

## İncelenen akış

Owned H025 HTTP → pinned0.41.0 RawRow model/provider allowlist → H023 observation/event → bağımsız attribution doğrulama/merge → mevcut SQL transaction/upsert → aynı dönem event kümesinde origin/grup toplamı → readonly Overview DTO → strict TS decoder → Coverage tablosu. Normalizer/store/collector çağıranları ve üç mevcut test kurucusu güncellendi; actor, bağlantı Apply/Undo, model/auth/reasoning, engine optimizasyon ayarları ve uyumluluk kataloğu değiştirilmedi.

Pinned `server.py::_classify_agent_from_log` client/stack/model/provider çıkarımı yapar. Bu değer gerçek kimlik/rota kanıtı sayılmadı; raw tags ve raw attribution nesnesi adaptörde okunmaz. Model/provider yalnız bounded gözlenen etiketlerdir. Native witness constructor origin'i UUID değeri + proxy request ID ile bağlar; upstream/ajan/ebeveyn kimlikleri runtime kapsamında opaque olur. **Pinned toplayıcı bugün bu witness'ı üretmez.** Constructor/eşleme/kapsam sözleşmesi fixture ile test edildi; gerçek ana/alt ajan ataması bu testlerle yükseltilmedi.

## Doğruluk ve korunmuş sınırlar

- Metadata enrichment H023 sayacının eşitlik karşılaştırmasından ayrıldı. Yalnız model/rol bilgisi eklendi diye token olayı conflict olmaz. Çelişen metadata unknown'a absorbe olur; sonraki aynı replay bunu yükseltmez. Sayaç çelişkisi için mevcut koruma sürer.
- Varsayılan unknown attribution eski schema1 payload'larda eksik olabilir. Current reader eski kayıtları okur; enrichment aynı event_id'yi ve ilk izleme oturumunu korur. SQL şeması, retention,4KiB event sınırı, dosya pin/hardlink/reparse koruması ve rollback yolu değişmedi. Eski binary'ye downgrade uyumu iddia edilmez.
- Query önce aynı opaque origin'in katmanlarını birleştirir; model adı ajan ID'si değildir. İstek kimliği sayısı distinct origin'dir; korelasyonsuz kaynakların aynı fiziksel olaya ait olduğu varsayılmaz. Kanıtlı farklı upstream aynı model olsa bile ayrı grup kalır. `verified` yalnız gözlenen kapsamda o alanın bütün kayıtlarına kanıt geldiğini söyler; tüm hesap/sağlayıcı/ajan desteği değildir.
- En çok64 satır: fazla gruplar sayıları ve toplamları korunarak açık Diğer satırına gider. Diğer satırının kimlikleri bilinmiyor diye etiketlenmedi; birden çok grup olarak belirtilir. Attribution durumları ana token temelini veya optimizasyon kapsamını değiştirmez.
- TS decoder dönem, toplam, origin/event sayıları, coverage statüleri, unique64hex grup/ajan/rota kimlikleri, bounded etiketler, role/parent ilişkisi ve Other satırı korunumu denetler. UI yalnız temizlenen alanları alır; beklenmedik kesinlik veya bozuk yanıt gösterilmez. Mevcut ağırlıklı token toplamı yeniden kullanıldı, bağımsız yüzde hesabı eklenmedi.

## İnceleme düzeltmeleri

- OpenCode enum'unun varsayılan snake_case yazımı `open_code` olurken ortak istemci sözleşmesi `opencode` istiyordu. Açık serde adı ve regresyon eklendi; farklı üretici/renderer etiketleri önlendi.
- Metadata farkı tüm NormalizedEvent eşitliğine katılsaydı eski bir kayıt model etiketiyle zenginleşince gerçek50 token farkı kaybolacaktı. Ayrı merge ve absorbing metadata conflict testi bu koşulu önce RED sonra GREEN doğruladı.
- Ham satırdaki doğru biçimde görünen attribution/route nesnesinin modelden bağımsız olarak witness sayılamadığı ayrıca sınandı; adaptör bunu yok sayıyor. Owner-bound HTTP canary/metadata testi source → store → query zincirini kapsar.

Yeni bağımlılık, renderer yazma IPC'si, kullanıcı hesabı veya global ayar eklenmedi. Yeni Coverage bileşeni modelden bağımsız props kullanır; istek yoksa ikinci boş panel üretmez. Mevcut tek Luna yalnız bu bileşen/CSS'i yazdı; completed/durdurulmuş olarak ana ajan devraldı. Veri/kimlik kararları, parser, uygulama, bağlı akış incelemesi ve kabul ana ajandadır.
