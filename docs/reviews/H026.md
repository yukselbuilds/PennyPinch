# H026 — Lead agent acceptance review

5 November 2026. The lead agent combined Ponytail review and the quality review. The review assumed one desktop user, H024 limits of 100,000 events and 128 MiB, and H025 samples every 5 seconds. It covered the attribution change. Performance at that load remained unmeasured.

<a name="incelenen-akış"></a>

## Paths reviewed

The H025 collector reads from its owned HTTP source. The pinned 0.41.0 adapter uses the RawRow allowlist for model and provider labels. H023 creates observations and events. A separate step validates and merges attribution. The store uses the existing SQL transaction and upsert.

The query calculates origin and group totals from the same set of events in the selected period. The read-only Overview DTO passes through the strict TypeScript decoder to the Coverage table.

The change updated the callers of the normalizer, store, and collector and three existing test builders. It uses the existing runtime actor and connection Apply and Undo paths. Authentication, model, reasoning, engine optimization settings, and the compatibility catalog stayed outside the change.

Pinned `server.py::_classify_agent_from_log` infers client, stack, model, and provider labels. The adapter accepts bounded observed model and provider labels and excludes raw tags and raw attribution objects. Identity and route require their own evidence.

The native witness constructor binds the origin to a UUID value and proxy request ID. Upstream, agent, and parent identities are opaque within the runtime. **The pinned collector does not produce this witness.** Fixtures covered the constructor, matching, and scope. Actual main and subagent attribution still needed separate evidence.

## Correctness and limits

- The normalizer checks enrichment separately from H023 counter equality. Adding a model or role label alone leaves the token event valid. A metadata conflict makes attribution unknown. Repeating the same metadata preserves that state. Counter conflicts use the existing guard.
- The current reader accepts older schema1 records and treats missing attribution as unknown. Enrichment preserves the same `event_id` and first monitoring session. The store keeps its schema, retention, 4 KiB event limit, file pin, hardlink and reparse checks, and rollback path. Downgrade compatibility still needed verification.
- The query first combines layers from the same opaque origin. The request count uses distinct origins. Combining sources requires evidence of correlation. Agent identity requires evidence beyond a model name. Proven separate upstreams keep separate groups even if they use the same model.

  The `verified` status requires evidence for that field in every record within the observed scope. Account, provider, and agent coverage beyond that scope needs separate evidence.
- The table shows up to 64 rows. It puts excess groups in Other and preserves their counts and totals. Other represents multiple groups. Attribution status does not change the main token basis or optimization scope.
- The TypeScript decoder checks the period, totals, counts for origins and events, coverage status, label bounds, and role and parent relations. It requires unique 64-character hexadecimal IDs for groups, agents, and routes. It also checks that Other preserves its counts and totals. The UI receives sanitized fields after validation. It reuses the weighted token totals for percentages.

## Findings fixed during review

- The default snake_case serialization for the OpenCode enum was `open_code`. The shared client contract requires `opencode`. The fix sets the serde name explicitly, and the regression checks that the producer and renderer agree.
- Comparing all NormalizedEvent fields could erase a real difference of 50 tokens when a replay supplied a model label for an older record. The fix merges metadata separately. The regression for persistent metadata conflicts first failed and then passed.
- The adapter ignores a raw attribution or route object even when it has the right shape. The test verified that the raw object cannot supply a native witness. The owned HTTP canary used fixture metadata and checked the path from source to store to query.

The change uses the existing dependencies and settings and keeps the renderer read-only. Account setup stayed outside the change. The Coverage component uses props independent of the model. When there are no requests, it omits the second empty panel.

The single Luna worker wrote the Coverage component and CSS. The lead agent took over after Luna stopped. The lead owned data and identity decisions, the parser, implementation, review of the connected path, and acceptance.

Formatting, builds, native checks, and isolated UI checks passed.
