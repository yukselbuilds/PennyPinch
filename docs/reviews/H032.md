# H032 — Theme and language review

7 November 2026. The lead agent applied Ponytail for acceptance. The review confirmed the existing themes and Turkish and English views on all main screens. Native testing found conflicting preference reads. The fix uses the shared store. Two engine error messages now match the explanation on screen.

The review assumed one local desktop app with overlapping Overview, Activity, and preferences reads at startup. Sustained load and performance still needed their own evidence.

The review checked `Settings → App.changePreferences/reloadPreferences → preferences client → get/save_preferences → PreferenceStore`, `Overview/Activity → MetricsStore.retention_days → PreferenceStore.operating`, and `RuntimeManager → PreferenceStore.operating`. It also checked `App.theme effect → matchMedia/data-theme → CSS tokens` and `language → root lang/Intl formatters`.

The narrow CodeGraph `get_preferences` query served as discovery. The team synced the index for 3 changed source files. The Luna worker reviewed text and locale. The lead reviewed the connected paths.

| Before | After | User effect |
| --- | --- | --- |
| `src-tauri/src/state/store.rs:252,309` used only a zero-wait OS mutex for reads and saves on cloned stores. A retention read could collide with a language and theme read and return busy at startup. | A standard-library mutex in the same StoreInner serializes calls before they acquire the OS lock. | The app loads the saved language and theme during normal startup without a second read. |
| `src/App.tsx:57,95` said the app showed the raw engine error code below. SnapshotNotice displays a translated explanation. | The text in both languages now refers to the visible explanation. | The error text matches what the app displays. |

The store keeps StoreLock, the Windows named mutex, revision and fingerprint CAS, validation, and atomic file replacement. It releases the mutex guard before it replies. Calls from the store do not reenter runtime or metrics, which preserves lock order. A poisoned local mutex returns the existing environment_blocked error.

The schema, defaults, operating preferences, model, authentication, routing, and measurement rules stay the same. If two writes queue on the same store with the same revision, the second receives a CAS conflict after the first succeeds. The existing busy protection still applies to separate stores and processes.

The parallel test used 4 readers with 16 reads each on the real file. It checked the saved values `en` and `dark` at revision 1. The reads kept the file bytes the same. The test failed before the fix. After the fix, 12 store tests passed.

The final gate passed 153 Node tests and 363 Rust tests. It ignored 8 opt-in tests.

The isolated Full-App fixture passed 48 screen and state combinations at 5 widths. It checked locale, system theme, manual changes, and save errors. Native testing passed in three sessions with two reopens. The 26 checks matched 171 current source and config inputs as well as artifacts and environment. [Evidence](../proofs/theme-language.md)

The native English app card displayed “1 installations” for a count of 1. The label is in `src/features/integrations/Applications.tsx:116`. The review recorded singular and plural wording as an optional change. Theme and language acceptance passed, and the lead closed the review.

**Decision. The review accepted local H032 at 31/51.** The lead found no open correctness or data loss issue that blocked acceptance. Windows 11, other operating systems, actual OS theme transitions, OS DPI, installation and release, sustained load, and live providers needed separate checks. H033 had yet to start.
