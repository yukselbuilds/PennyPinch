# H031 — Operating preferences review

7 November 2026. The lead agent applied Ponytail for acceptance. Operating preferences extend the existing atomic record. The next manual Start applies the saved tool protection. The app confirms the effective setting through the engine's health and readiness acknowledgement. Windows startup uses a separate, fixed OS value that the app checks for ownership.

The review assumed one local user, one app, and the existing metadata collection interval of 5 seconds.

The settings path is `Settings → App.changePreferences → preferences → save_preferences → PreferenceStore → Lifecycle/MetricsStore`. The runtime path is `RuntimeLayout → controller safe env → helper → pinned CLI/health → ReadyInfo/RuntimeView → operatingSettings → Settings`. The startup path is `set_autostart → lifecycle guard → named lock → fixed HKCU value/fingerprint → snapshot`.

The change uses the existing language and theme settings, Activity and Overview decoders, and owned shutdown path. The lead synced CodeGraph and used a narrow save_preferences query for discovery.

| Before | After | Why |
| --- | --- | --- |
| Retention and the Activity decoder used a fixed limit of 30 days. | One retention setting applies 7, 30, or 90 days to all readers. | The stored records and query replies reflect the same selection. |
| Extending retention could restore older dated events from an engine replay. | The transaction uses one date floor and migrates schema 1 to 2. | The date floor keeps deleted history out of storage. The change requires no request-ID tombstone store. |
| The language and theme object could drop new fields. | The store preserves the latest saved fields and accepts legacy saves. | A theme change preserves protected tools. |
| Refresh after save held the mutation lock. | Saving releases the lock before refresh. | The UI can refresh the saved and effective states immediately. |
| The footer and dialog promised hiding when close-to-tray was off. | The effective close_to_tray snapshot and event determine both messages. | The messages and the X action reflect the user's selection. |

The app limits list size and keeps the ASCII names sorted and unique. The engine reads the list as configuration data. Its environment excludes global credential variables. The startup writer preserves stale or different values.

The registry offers no OS compare-and-swap operation. A named mutex serializes the app's own writers. The writer checks fingerprints before and after the write. The source documents the race with an external writer after the last check.

The change preserves file CAS and atomic replacement, SQLite transactions, owned processes and ports, and existing error handling. The review found no open correctness or data loss issues.

The final candidate passed 153 Node tests and 362 Rust tests. It ignored 8 opt-in tests. Formatting, TypeScript, Vite and native builds, Python checks, and the extra real pinned-engine test passed. Native checks passed for Sky mouse and keyboard input and reopen. The isolated UI tests passed 8 behavior groups.

The 26 checks matched 171 source and config inputs as well as the final artifacts and environment. The lead reviewed the source, connected paths, and evidence directly. The single Luna worker wrote the limited frontend slice. Development duration and savings remained unmeasured. [Evidence](../proofs/operating-preferences.md)
