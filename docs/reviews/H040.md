# H040 — Stable client address review

21 October 2026. The lead agent completed local H040 acceptance on Windows 10. The final section records the acceptance and its limits. The earlier decisions and checks remain below.

<a name="tarihsel-dilim-incelemeleri"></a>

## Historical reviews

The review accepted the architecture. It keeps a Rust-owned TCP listener at a stable address on loopback. The listener connects to the existing Python engine at its dynamic, ownership-checked address. The design adds no HTTP parser, header or body changes, or speculative direct-provider fallback. The endpoint identity and backend generation stay separate. TCP keep-alive connections stay with their original generation. [Decision](../decisions/003-connection-ingress.md)

The initial review added a required protection. The Windows listener in Rust leaves `SO_REUSEADDR` and exclusive bind unset. The Windows contract requires setting `SO_EXCLUSIVEADDRUSE` before binding to get exclusive access. A local negative test must reject a second listener that uses `SO_REUSEADDR` before the review accepts protection against endpoint sharing. [Rust 1.92 listener source](https://github.com/rust-lang/rust/blob/1.92.0/library/std/src/sys/net/connection/socket/mod.rs) · [Microsoft contract](https://learn.microsoft.com/en-us/windows/win32/winsock/so-exclusiveaddruse)

The acceptance plan specifies these limits.

- The first endpoint publish is atomic and preserves an existing record. If the saved port is busy, both the state and address stay the same. The bounded state reader checks the schema, duplicate keys, paths, and reparse points.
- The relay checks the PID for the exact server-side TCP 4-tuple before it forwards payload. The relay blocks forwarding if the PID is ambiguous or the generation changes. It does not retry or replay payload.
- The relay preserves byte order and half-close. It bounds connections, buffers, idle time, lifetime, and drain time. A TCP connection count measures connections. Streams have their own count.
- Stop or exit first blocks new routes. It starts request-aware graceful stop for the owned engine, then drains the remaining TCP connections within a limit. An idle keep-alive connection does not delay engine stop until the connection count reaches zero. Forced or incomplete streams cannot count as graceful success. The actor and caller use compatible time budgets.
- Endpoint preservation when the app fully exits has a separate lifecycle contract. The H030 and H034 checks and the H017 connection and rollback checks still apply. Pause and CCR continuity need their own evidence beyond H040.
- Final acceptance requires the production manager, synthetic authentication, protocol, and SSE fixtures, a real pinned engine restart, and the final local quality gate. Windows 10 evidence applies to that environment. Windows 11 and live authentication, model, and subagent compatibility need separate evidence.

## Final acceptance on 21 October 2026

**Local H040 acceptance passed on Windows 10.** The C source review accepted a separate endpoint TTL and listener guard. A successful route publish refreshes the ready observation. The checks covered held handles, three real JobObject memberships, generation, process chain, and listener.

The actual Job had 5 members, including two console hosts. The fix changed the membership count check from exactly 3 to at least 3. The check needs ownership evidence beyond a basename. The no-route fixture requires a fixed socket close error and 0 response bytes. A timeout or received data fails the test. The review checked duplex offsets, buffers, deadlines, peer verification before payload, no replay, and bounded cleanup. It found no blocker.

The full Rust suite passed 68 tests, with 0 failures and 2 opt-in tests ignored. The separate pinned engine lifecycle check passed 1 test in 36.66 seconds. The embedded build passed without warnings. Formatting, checks, and static frontend evidence matched. Source fingerprints stayed the same.

Native OCU used physical input for Start, Stop, and restart. The checks observed HTTP 200 health through stable ingress and Stop with an idle keep-alive. The app exited normally from Ready with code 0. A new process used the same address and ID, then exited with code 0. The final owned process and listener count was 0. The preference hash matched. [Final evidence](../proofs/connection-ingress.md) · Quality record (local receipt `work/proofs/connection-ingress/final-quality.json`) · Native record (local receipt `work/proofs/connection-ingress/native-proof.json`)

This acceptance covers transport and runtime. The A2 synthetic authentication and SSE checks verify byte behavior in fixtures. Shutdown during active SSE on the pinned engine and live client, model, and subagent checks retain their own scope.

H029 and H030 cover active streams. H011 and H028 cover pause and CCR. H041 covers sustained backpressure and performance. Windows 11, clean hosts, installation, and release also remained open. Direct fallback stayed off. Endpoint preservation after full exit has separate tray and config rollback requirements. The team updated TASKS and the checkpoint, then stopped before H017.
