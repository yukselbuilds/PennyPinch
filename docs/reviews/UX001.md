# UX001 — Visual refresh and connected-flow review

6 November 2026. The user rejected the existing design. The lead agent took ownership of visual direction and implementation. The lead applied the project design guide and Emil design engineering. The lead worked without a separate worker. [Design guide](../../DESIGN.md)

| Before | After | Why |
| --- | --- | --- |
| 252px navigation, letter-spaced uppercase labels, and mixed Unicode icons | 200px navigation, labeled SVG icons, and a simple wordmark | Less visual noise leaves more room for content. `src/App.tsx`, `src/components/Icon.tsx` |
| Separate boxes with equal visual weight and a large dash for unknown values | One savings surface, a separate control area, and meaningful empty/read-error states | The percentage, amount, and engine action get different levels of emphasis. `Overview.tsx`, `overview.css` |
| 9–10px helper text and buttons | 12px shared small text, 14px body text, and large tabular numerals for measurements | Text stays readable in native windows and at different scales. `src/styles.css` |
| Date labels shrink inside a small SVG panel | HTML date labels and data bars from the same measurement buckets | Chart values stay readable without changing their meaning. `SavingsChart.tsx` |
| Identity details add card weight to the main table | Keep the application/model table. Open identity and scope details by keyboard. | Unknown identities and source notes remain available. The main function stays clear. `Coverage.tsx` |
| Generic hover/press examples | Brief feedback on pointer press. focus-visible, keyboard access, and reduced-motion settings remove motion. | Daily controls do not wait for an animation. `overview.css` |

The review followed real UI actions through the existing typed client to the native manager and engine. It also followed preference actions through the existing client to persistent storage. The bridge, auth, model, reasoning, runtime control, ownership of saved settings, and data queries stayed the same. Token and cost rules stayed the same. The review checked native Start, Pause, Resume, Stop, and restart. It checked four screens and isolated states of the real App hook and client. The UI invents no number or chart when data is absent. It preserves measured 0 and negative results.

The first render led to one correction package for palette, empty space, and small text. The final candidate had no open acceptance-blocking finding. The first mixed fixture supplied the wrong count of comparable events for the real decoder. The team corrected only the fixture. The team changed the test's 40s startup wait to fit the product's 100s native and 90s helper limits. The team left the product timeout unchanged. This did not accept engine startup performance.

The final candidate had matching build and test fingerprints across 152 source/config inputs. It passed 138 frontend and 349 Rust tests. It ignored 6 opt-in tests. Native and visual runs exited with code 0. Owned debug ports closed. Existing settings stayed the same.

The result covers local Windows 10. Live providers, other operating systems, installation, and sustained performance still needed evidence. Sample percentages describe fixture data. Development savings remained unmeasured. [Evidence](../proofs/ui-taste.md)
