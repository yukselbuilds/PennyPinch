# H010-e değişiklik incelemesi

14 Kasım 2026. Ana ajan, Ponytail full/review ve mevcut kalite incelemesi. Değişiklik gerçek OpenCode V2 CLI'sinin izole private server yolunu iki protokolde Headroom motoruna bağlayan opt-in test yardımcısıdır. Ürün adaptörü, uyumluluk kataloğu, kullanıcı ayarı veya paket değiştirilmez. [Kanıt](../proofs/opencode-v2.md), [programatik kabul](../proofs/opencode-v2.json).

İncelenen akış: resmî archive/checksum/executable pin → yeni global config/cwd ve allowlist env → `run --standalone` → özel CLI server → sahipli Headroom motoru → yalnız sentetik loopback sağlayıcı → JSON text/terminal step → CLI/server/job süreç0 → normal motor kapanışı. Mevcut bounded-output, environment, SSE formatter, fixture runtime ve Engine yardımcıları tekrar kullanıldı; çağıranların sözleşmesi değiştirilmedi. Yük varsayımı opt-in tek geliştirici, iki sıralı kısa model turudur.

Düzeltilen somut koşullar:

1. V2 normal komut, var olan servise bağlanabilir (`bench/opencode/v2.py:244`, pinned server-connection/standalone kaynakları). Test yanlış profile model isteği gönderebilirdi. `--standalone`, boş özel HOME/XDG ve kendi global-config cwd'si seçildi; her komutun job'ında exit sonrası süreç0 gerçek koşuda doğrulandı. Bu yalnız private server kabulüdür.
2. Deny-all `integration.use`, izin verilen özel provider'ı da kaldırdı (`bench/opencode/v2.py:42`, pinned config/plugin/policy.ts). Kullanıcı etkisi teknik testte `provider.no-route` idi; ilk başarısız kayıt korunur. Son config yalnız aynı provider/integration için iki izin açar; model/tools ve diğer provider'lar için kapsam genişlemez. Config testi bunu negatif varsayımlarla kilitler.
3. Hatalı final/step veya rota/model/auth tek başına CLI exit0 ile geçebilirdi (`bench/opencode/v2.py:67`, `bench/opencode/v2.py:78`). Exact final, bir terminal step ve ayrı wire kontrolleri zorunludur; altı odaklı testte bozulan girişler reddedildi. Sentetik usage tasarruf olarak dönüştürülmez.
4. Job ataması başarısızsa, henüz job'a girmemiş doğrudan CLI yalnız wait ile bırakılabilirdi (`bench/opencode/v2.py:152`). Finally, kapanmayan kendi Popen handle'ını kill/wait ile sonlandırır. Negatif test assignment hatasında bu cleanup'ın çalışmasını doğrular; diğer kullanıcı süreçleri aranmaz veya kapatılmaz. Bu kaynak değişimi önceki olumlu runtime kaydını son aday için geçersiz kıldı; altı test ve iki protokol akışı yeniden alındı.

Altı odaklı test ve iki gerçek CLI/Headroom protokol akışı PASS; 645 runtime girdisi/config/ortam aynı. Önceki tam ürün kapısının 332 girdisi/araç/OS eşleşmesi programatik denetlendi; kapı tekrar edilmedi. Yeni helper eski kapının kapsamı gibi sunulmaz. CodeGraph sync başarılı. İnceleme sonunda açık doğruluk/veri kaybı bulgusu yok.

Karar: yerel H010-e dilimini kabul et; ana H010 açık. Kontrol edilmeyenler: gerçek inference/auth, V2 native discovery/Apply/Undo/retrieval/alt ajan, normal service ve Desktop GUI, başka OS, paket kurulum/yayın. Bu sınırlar mevcut ürün V2 engelini kaldırmaz. Geliştirme token tasarrufu ölçülmedi.
