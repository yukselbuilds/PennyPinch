# H010-c change review

14 November 2026. The lead agent applied Ponytail full, Ponytail review, and the current quality review together. The benchmark checked that the real OpenCode task tool starts a child through the native product connection and preserves the user's model change. The test kept the scope limited. Product source, distribution, and general client settings stayed the same. [Evidence](../proofs/opencode-subagents.md) · [Programmatic acceptance](../proofs/opencode-subagents.json)

The native Start, Preview, and Apply actions wrote JSONC and ownership atomically. The pinned CLI used the task tool to start a separate child session. The saved provider routed through owned ingress to the engine. The test verified MCP, CCR, witness values, and final responses for both roles. The GUI exited normally. The existing native keep-state Undo completed.

Task metadata and exported session data verified parent and child identity. Model names and fixture prompts alone could not verify that identity.

Resolved test findings follow.

1. The fingerprint helper used the project root and rejected a file in the separate app state root (`bench/opencode/subagents.py:229`). The GUI and model turn did not start. The test now hashes only explicitly owned state files in a separate `fixture-state/` namespace. Other roots remain outside its read scope.
2. Responses user blocks carry `input_text`. The tool text reader incorrectly rejected those blocks in a real turn (`tests/fixtures/opencode/subagent_fixture.py:31`). The parser now uses the narrow text and input_text schema for user blocks. A negative test rejects images and malformed blocks.
3. The server-side CCR envelope includes `original_item_count`. The two-field MCP check rejected a complete result (`tests/fixtures/opencode/subagent_fixture.py:60`). The test checks the three Responses fields and the integer count against the pinned package source. The hash and original content match exactly. Partial content still fails the negative test even with added metadata.
4. Passing scenarios stayed only in memory when a later scenario failed (`bench/opencode/subagents.py:108`). The runner now writes each passing scenario to a new JSON file. A later failure still fails the whole run. The rest of the steps remain unverified.

The expected load was one user, three sequential runs, and at most one foreground child. The helper provides CLI and export time limits and a 4 MiB limit for stdout and stderr. HTTP and MCP inputs have limits. Task permissions allow two named fixture children. Other tools can only return fixed data or retrieve content. The profile disabled shell access, file reads and writes, network, nested and background agents, and auto and yolo flags. Authentication was synthetic. Reports excluded exports and HTTP bodies. The test sent no physical input to the user's foreground app.

The final candidate passed three native scenarios and nine focused tests. The source, test, config, CLI, runtime, binary, Python, and environment fingerprints matched. The 332 product inputs and tools still matched the evidence for 222 Node and 448 Rust tests, formatting, and builds. The team reused those results and kept the three failed records. The team used CodeGraph to find the shared normalizer and updated its index for three new files. Runtime verification and token savings require separate evidence. Dependency, worker, model, and global settings stayed the same.

**Decision.** The local Windows 10 slice passed. The review found no issue that blocked acceptance. The scope was this change. Live providers, model quality, TTFT, billing, TUI, V2, Desktop, and a second operating system remained unverified. Development token savings remained unmeasured. Main H010 stayed open.
