# H010-d change review

14 November 2026. The lead agent applied Ponytail full, Ponytail review, and the current quality review. The test helper connected the full OpenCode TUI in a real terminal to the existing native fixture flow. Product source, general client settings, account and model settings, and distribution stayed the same. [Evidence](../proofs/opencode-tui.md) · [Programmatic acceptance](../proofs/opencode-tui.json)

The native Start, Preview, and Apply actions saved JSONC and ownership. The worker opened the full TUI in a real PTY. It used the terminal to select the model and send a message. The test observed tool use, CCR, and final responses for both roles. It checked the session list and export. The TUI and GUI exited normally. The existing native keep-state Undo restored the settings.

The runner reused the H010-c native lifecycle with explicit fixture, runner, and source parameters. It kept the existing writer, engine, and application. The default CLI benchmark caller and settings factory stayed intact.

Resolved findings and acceptance scope follow.

1. The client and MCP processes could remain after an interruption of the terminal helper (`bench/opencode/tui.py:106`). The test used the existing Windows KillOnCloseJob. The real run recorded Job membership and exit code 0 for the native terminal child process. All three terminals recorded forced=false. The test verified normal shutdown separately.
2. During resume, the CLI hint did not replace the previous TUI model (`bench/opencode/tui.py:106` and the pinned `local.tsx` model-store and fallback order). The fixture rejected the wrong model request. The record kept the failed run. Final acceptance required a visible `/models` selection and the actual selector in the export. The CLI hint remained unverified as an override.
3. The menu could not distinguish fixture models with the same visible name (`bench/opencode/tui.py:20`). The test changed only the fixture labels. Provider and model IDs stayed the same. The review checked title and category search in the menu source. It checked the actual selection in the TUI footer.
4. The controller stopped and lost the prior fixture settings bytes that existed only in memory (`bench/opencode/subagents.py:177`). The test now writes an initial record only inside its owned proof root. It first validates a single bounded loopback setting. The negative test verified that invalid content or a remote URL produced no write. The final normal run restored settings byte for byte. The earlier reset after interruption remains recorded as a reset.

The expected load was one user with three sequential terminals. Each terminal had a 180 s limit. Metadata commands had limits of 30 s and 4 MiB. The GUI had a 900 s limit. A wrong parent, child, or model causes failure. Missing tools or final responses, wrong terminal input, and permission differences also cause failure. Parent identity requires evidence beyond the model name. The report kept real authentication data, request bodies, and transcripts out of its records.

The test sent no physical input to the user's foreground app. Only the fixture disabled the title agent. Other tools and child agents had narrow permissions.

The final candidate passed three full TUI turns, 19 focused checks, and normal native Undo, GUI exit, and listener closure. The 363 native inputs and tool and environment fingerprints matched. The team reused the prior Node, Rust, formatting, and build results for 332 matching product inputs. Separate tests covered the new test source.

CodeGraph served only for discovery and index synchronization. Runtime verification and development token savings require separate evidence. The change added no dependency or worker and left global settings intact.

**Decision.** The local Windows 10 TUI slice passed. The review found no issue that blocked acceptance. Its scope was this change. Live providers and authentication, model quality, TTFT, billing, V2, Desktop, and other operating systems remained unverified. Main H010 stayed open.
