# H012 main acceptance review

The lead agent owned the architecture, measurement definitions, and compatibility scope. The review matched runtime selection, native IPC registration, adapter plans and receipts, measurement DTOs, and the support catalog to the existing evidence. It covered existing product behavior.

- The documentation omitted the V2 plan and receipt schema tag and the new MCP path. An implementer could therefore use the V1 path for V2. The contract documents the shared ownership slot, optional tag, permission and bridge guards, and atomic Undo. [Current contract](../contracts.md#2-ayrı-durum-makineleri)
- The measurement section treated old totals and states from the runtime placeholder as period query fields. This could mix separate DTOs. The contract documents `before_tokens`, `after_tokens`, `saved_tokens`, `saved_percent`, and `totals.status`. It describes per-request `MetricSummary` and collector state `collection.status` separately. [Measurement contract](../contracts.md#5-içeriksiz-ölçüm)
- H012 documentation acceptance waited for external tests even though the catalog could represent unknown combinations. That wait left the architecture decision out of sync with the recorded evidence. The review closed H012 under K3 and the original acceptance criteria. Account, OS, and release limits retain their own records. [Runtime decision](../decisions/002-runtime.md#uygulama-ve-yayın-sırası)

The verifier matched all 39 IPC commands once each. It checked catalog statuses against the Rust allowlist and resolved evidence and local document links to real files. A source, catalog, dependency, tool, or environment mismatch blocks acceptance. The product inputs matched, so the review reused evidence for 222 Node and 462 Rust tests and the related build checks.
