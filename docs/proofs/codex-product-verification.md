# H019 — Codex product verification

23 October 2026. **H019 accepted for the first Windows CLI slice**, on Windows 10 Pro 22H2 x64, build 19045. The native result is a verified completed response with two visible, unclassified CLI error notifications; it is not an error-free CLI or general compatibility PASS. Older H019 proofs remain historical observations rather than current application state.

## Delivered behavior

Applications discovers the measured Codex CLI `0.163.0-alpha.11.2`. The existing owned config planner/apply/undo retains model, reasoning and unrelated bytes. The separate **Test in a new process** action invokes a bounded real CLI test through the selected installation, Tauri manager and owned Headroom runtime. The UI explains account usage and the new-process scope before the action.

The new test uses normal CLI sign-in and settings with `--ephemeral`, a read-only sandbox and one process-only endpoint override. It does not set a model, reasoning level, provider, authentication method or agent count. It does not resume another chat, edit saved client config, copy an auth store or require a new login.

PASS requires an exact unpredictable marker, terminal turn completion, exit 0, the exact CLI PID observed connecting to the application-owned ingress, unchanged selection/config/runtime and a strict correlated IPC reply. Concurrent tests, malformed output, stale state and unsupported routes cannot produce PASS. A Windows job owns the test process; shutdown and spawn registration are serialized so closing the application cannot miss a newly started child.

## Scope and remaining limits

This is the first Windows CLI product slice. Desktop, other provider/auth routes, future CLI binaries, Windows 11, macOS/Linux native behavior and clean-machine distribution remain untested here. A successful new-process test does not prove that an already open chat adopted a saved endpoint. Its UI deliberately retains unknown saved-config adoption and untested general auth/subagent coverage.

The separate [native child-to-wire proof](codex-agent-native-route.md) established a real child lifecycle, exact child UUID/transport match and model preservation. Unchanged engine/relay/CLI fingerprints allow that narrow transport evidence to be reused; the product test itself creates no subagent. It does not establish every possible provider/model/agent route or per-agent savings. The development worker's Luna model is not a product restriction.

The two additional CLI errors are unclassified and unresolved; protocol investigation remains tracked in H008. They are displayed explicitly, and do not become a clean `passed` result. A failed/aborted turn, unexpected tool, malformed/unknown item or missing/duplicate marker/terminal remains a failure regardless of generic error order. Current response-route acceptance does not close that broader investigation.

Historical unidentified Rust failure, partial short CLI event exporter and earlier header-diagnostic model-list relay failures retain their original limits in the earlier proofs. They are not described as resolved by an unrelated current PASS. No new CI or push is claimed; this candidate's frontend and native results are local.
