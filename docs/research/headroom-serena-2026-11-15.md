# Review of Headroom 0.44.0 and Serena 2.1.0

15 November 2026. This review covered the stable Headroom 0.44.0 tag, release notes, Learn and proxy sources, and current documentation. It also covered the Serena 2.1.0 release, symbol tools, language servers, project settings, memory, and REPL documentation. The local comparison uses the pinned Headroom 0.41.0 engine and the project CodeGraph. [Headroom release](https://github.com/headroomlabs-ai/headroom/releases/tag/v0.44.0) · [Headroom docs](https://docs.headroomlabs.ai/llms.txt) · [Serena release](https://github.com/oraios/serena/releases/tag/v2.1.0).

## Headroom

| Area | Source behavior and project decisions |
| --- | --- |
| Compression and retrieval | Version 0.41.0 already has a content router, `--lossless`, cross-turn deduplication, and local CCR. Version 0.44.0 adds a lossless `/v1/compress` option, with other changes for bare path lists, table columns, search order, and JSON lines named in prompts. Initial candidates are exact repeats, noisy logs, and format-preserving transformations. AST, images, RAG, and general text compression are broader experiments that need separate task-quality tests. | Cache and streams | The published live-region approach targets only changeable new content. The pinned engine also has a recompression option for cold prefixes. Use an A/B test to check that the session prefix, cache reads and writes, and CCR access stay intact. Put the 0.44.0 client-disconnection and stream-resumption fixes in the first package candidate. Add a separate test for `--no-ccr-response-handling` to confirm that the model can receive original content through the client path. [Cache](https://docs.headroomlabs.ai/docs/cache-optimization) · [Context management](https://docs.headroomlabs.ai/docs/context-management) · [Release notes](https://github.com/headroomlabs-ai/headroom/releases/tag/v0.44.0). |

Keep direct engine counters, price estimates, and the product's local compression difference on their own measurement bases. New observation and chat ID fields may simplify local records after checks verify their behavior with real clients and subagent ownership. <a name="learn-ne-yapar"></a>

### What Learn does

- Learn normalizes tool calls from past client records. It derives short project advice from patterns. Examples include repeated failed commands, wrong file paths, searches that are too broad, and repeated requests for the same result in pieces. Claude Code and other clients have separate project locations and write destinations. The normal preview command prevents file writes. `--apply` can change instruction or memory files through the selected writer. [Failure Learning](https://docs.headroomlabs.ai/docs/failure-learning) · [0.44.0 CLI](https://github.com/headroomlabs-ai/headroom/blob/v0.44.0/headroom/cli/learn.py).
- Error analysis can send a summary from a local scan to a model. The pinned source uses API keys, the selected model, and CLI options. This can also occur during preview. The `--verbosity` option uses a separate workflow. It processes behavior signals locally, with the option to use an LLM for judgment. Applying a length setting can change the response format of the running engine. [Analysis backends](https://github.com/headroomlabs-ai/headroom/blob/v0.44.0/headroom/learn/analyzer.py#L160-L205) · [LLM call](https://github.com/headroomlabs-ai/headroom/blob/v0.44.0/headroom/learn/analyzer.py#L996-L1038) · [Length option](https://github.com/headroomlabs-ai/headroom#output-token-reduction).
- Only the 0.41.0 `detect_loops` function ran locally. Synthetic repeated failed commands and repeated reads each produced one candidate. A single failure produced no candidate. The five required test runs after code edits used the same command, so they also produced a candidate. The analysis layer must tell repeated commands after source changes from repeated commands in unchanged code. Model-generated advice and token savings require separate tests. See `work/proofs/optimization/learn-probe/a281db6a3806/result.json` for the local result.
- Run the first pilot only on selected synthetic examples in the project context. Compare the suggestions with the current `AGENTS.md` and `WORKFLOW.md`. It requires a matching error and the tool call that resolves it, a relevant source or tool fingerprint, and a short suggestion in preview. Keep repeated acceptance tests that run because the source changed. Evaluate the record and rule draft without automatic file writes. In the next real-task A/B test, measure the cost of generating and transferring an instruction against prevented repeats. [Project workflow contract](../development/WORKFLOW.md).

## Serena

| Area | Use in our project |
| --- | --- |
| Symbol and file reading | The free language-server backend can return symbol bodies, file outlines, and symbol references. These are candidates to complement CodeGraph's fast scan of static relationships. Start with `find_symbol`, `get_symbols_overview`, and `find_referencing_symbols`. Verify runtime boundaries such as Tauri IPC with real source and tests. [Tool list](https://oraios.github.io/serena/01-about/035_tools.html) · [Our CodeGraph](../development/codegraph.md). |
| Editing and refactoring | Changing a symbol body, inserting code by symbol, and renaming through language-server calls may help. If the first read-only pilot shows value, accept editing only in an isolated example with a diff and relevant test. Some dependency and debugging features belong to a paid JetBrains plugin. This pilot uses only the free path. [Feature matrix](https://oraios.github.io/serena/01-about/025_features.html). |
| MCP context and startup cost | Users can configure tool lists, mode, and project scope. In Headroom's own plugin change, the reviewed automatic Serena setup added about 5.9 thousand tokens to schemas available at startup. It took about 6 seconds to start. These values belong to that setup. Our pilot measures schema, output size, and cold/warm calls separately with a small set of symbol tools. [Headroom experiment](https://github.com/headroomlabs-ai/headroom/pull/4509) · [Serena configuration](https://oraios.github.io/serena/02-usage/050_configuration.html). |
| Memory and onboarding | Serena has Markdown memory files at project and global scope. We can test on-demand reference to content with the existing `AGENTS.md` and a short handoff note. The first pilot does not need a new automatic memory layer. [Memory and onboarding](https://oraios.github.io/serena/02-usage/045_memories.html). |
| REPL, settings, and lifecycle | The V2 REPL can run several queries in one operation, return a narrow result, and execute Python. The first pilot stays with the classic tool interface. Record project-specific state, selected language server, time limits, and output limits. Global memory, shell, writes, and dynamic backend changes are outside the first comparison. [REPL and tools](https://oraios.github.io/serena/01-about/035_tools.html) · [Work limits](https://oraios.github.io/serena/02-usage/070_security.html). |

## Implementation order and decision experiment

1. Set up usage measurement with full request identity and engine generation. On the review date, verification began on Windows 10 with the Anthropic Messages engine. Other protocols need their own acceptance for provider counters.
2. Evaluate 0.44.0 as a separate package candidate. Compare pin verification, owned process and port, installation, SSE/WS, cache/CCR, and settings rollback with the same tests. Test lossless output and exact-repeat information without changing the system prompt or prior prefix.
3. Select one log/debug task and one normal coding task with the same repository state, model, reasoning effort, and tool permissions. Run compression-on and compression-off arms several times in reverse order. Verify test success, changed files, and preserved evidence. Record total provider input/output, cache reads/writes, extra turns, and duration. Keep prior fixture results for local engine settings as separate data.
4. Compare Learn and Serena pilots with this baseline. Learn adds value only if it produces a small number of verifiable project suggestions. Serena's use scope depends on whether it returns correct references for the same query with less context and offsets setup and schema costs.
