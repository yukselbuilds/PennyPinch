## Purpose and contracts

An NSIS current-user x64 installer provides a self-contained UI and a fixed CPython/Headroom payload without requiring development tools. The base installation contains its own files; user state is not written into the installation directory, and existing app-local state/ownership/atomic-write contracts remain in force. The installer does not automatically route clients or sign in to accounts. H042 separately covers updates/installed-version rollback; H038 separately accepts safe uninstall integrity.

Do not change the development manifest or old payload. The package uses a separately source-controlled Windows manifest whose only difference is engine.payload_root set to payload; all other fields remain identical and pinned. The Rust installer layout validates the resources/runtime root and release manifest hash. Packaging completes atomically into a new staging directory only after source validation; reparse points/path escapes and modified payloads are rejected. Source caches/workspace/auth/logs are excluded from the bundle. Vendor files are not modified; transferred source gets a record of commit/file/change/license.

WebView2 availability is checked through Tauri's supported installer path; if absent, the bootstrapper's internet requirement is stated clearly. Users do not need to install Python/Node/Rust. Bundler tools downloaded during development stay in the project cache. This is an unsigned development preview; it does not claim signed release status and adds no payment/certificate. Do not blindly remove existing pinned proxy dependencies; record actual component size and optional ML/MCP/RTK boundaries.

## Ordered acceptance

The first deep-test target was 113 characters; although NSIS returned exit 0, two .pyc files whose full paths were 261/271 characters long were missing. This candidate is not complete installer acceptance. Without changing Windows-wide settings, the installer rejects with a clear error/exit 2 before copying when the root exceeds 100 UTF-16 code units; it must not skip files. Staging checks that every pinned file and directory path fits Win32 limits under that root; if the payload changes, check the budget again. Validate a shorter target containing spaces/Unicode and long-path rejection separately with the real installer. Unsupported long paths are not silent success.

The local installer experiment uses an app-owned empty project/work target and only newly created state directories. Existing account-profile contents are not read or copied; structural metadata is compared. The test state archive uses the explicit additional root %LOCALAPPDATA%\HeadroomDesktop-QA-H037. A CODEX_HOME fixture is bound in the child app's environment instead of using real Codex settings; under the existing transaction contract it is on the same disk as state. A fixture on another disk was safely rejected and left unchanged; cross-disk transaction support is not added to this task.
