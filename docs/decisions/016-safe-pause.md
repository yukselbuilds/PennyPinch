## Contract and scope

- Pause does not change the engine, endpoint, client config, auth/model/reasoning, or agent count. Generation-bound app control stops compression decisions for new requests. A request accepted earlier completes using its own snapshot. There is no POST replay mid-stream, switch to direct forwarding, or process restart. Start/Pause/Resume is the routine action. Stopping the engine is a separate secondary action.
- Pinned 0.41.0 skips Anthropic cached-prefix replay on the normal optimize=False path. Responses uses a different compression-unit/cache path. First, replay is tested with the real pinned engine and a local upstream. Production integration and UI are added only after this evidence. Vendor source is not modified on disk. The app-owned overlay is installed only with exact version/source fingerprints.
- The engine overlay keeps the decision stable for the duration of a request. Anthropic reuses the previously sent prefix with normal cache-control/opaque protection. For Responses, compression stops only for new content. Previously prepared/sent input and the same tools prefix are preserved within the model/auth/route and verified conversation lineage. Provider cache-hit information is not invented. The existing CCR store remains accessible in the same engine process within its current 7200 TTL.
- Prefix matching uses existing pinned lineage helpers. Different models/routes/identities and divergent sub-conversations are not mixed. State stays in RAM. Content or control secrets are not placed in metadata/log/export. If source/size/capacity evidence for safe replay is unavailable, return a fixed error/unknown rather than success or silently corrupting the prefix. Limits are made concrete in focused tests before implementation.
- Private loopback control reaches only the app-owned engine listener. The ephemeral control secret is carried only in-process/private bootstrap and the ready message. It is not present in public DTOs or persistent state/logs. Commands are bound to generation and revision. Wrong/ended generations, foreign listeners, malformed requests/timeouts, or negative acknowledgements do not count as success. No other engine/runtime is managed.
- The renderer shows only typed native commands and a snapshot after a real acknowledgement. A second lifecycle/control action is locked while one is pending. A late response cannot overwrite newer state. There is no optimistic paused/enabled state after an error. Recovery from unknown requires a fresh check. Active stream count remains null unless verified from its source.

## Three acceptance flows

For Anthropic, prompt content and the `cache_control` placement directive are verified separately. The engine's default breakpoint is not moved to a new tail during pause. Resume may advance the breakpoint under normal engine policy. Every other previous prompt/opaque field must remain byte-identical. With a fixed explicit client breakpoint, the entire message JSON must also remain identical. The client's marker/TTL is never changed. Unchanged prompt segments and breakpoint management in a growing conversation were checked against the [official cache contract](https://platform.claude.com/docs/en/build-with-claude/prompt-caching). Provider cache-hit/discount success is not inferred from a local fixture. The first test differed only in the engine's `cache_control` position. This distinction was established from source and a metadata-only diff, and other fields were not excluded from acceptance.

1. With the real pinned engine and isolated HTTP upstream, start a compressed turn → gated active SSE → pause ack → completion of the same POST with the same model/auth/reasoning → prefix bytes/CCR retrieval in the same conversation → new raw tail → resume → compression decision active in the same conversation, prior prefix preserved, and actual compression of suitable new content. The default coding/cache protections do not promise that every new tail will be shorter. Positive compression is also tested in an additional clean conversation with the same engine/model/profile, and the prior conversation's actual tail result is recorded separately. Responses, Chat Completions, and Anthropic paths are evidenced separately. WebSocket support is claimed only if frame boundaries are separately verified.
2. Wrong generation/revision/secret/shape, failed control, or source/capacity limit → fixed error, history preserved, no POST replay, and no foreign process/config changes. Prior successful evidence is reused only when fingerprints match.
3. In the native Graphite UI, test Start/Pause/Resume pending/ack/error behavior and keyboard/narrow layout. Secondary engine stop is separate. Review the source → helper/controller → Rust manager → IPC → UI chain. Run one full local gate on the final reviewed candidate. Obtain real native acceptance and update TASKS/checkpoint and commit/push. Stop when the main task is complete.

Focused verification starts with content-free metadata/fingerprint runs under `work/proofs/pause/`. Do not assume a command is ready until the existing file is verified. The final gate uses the commands in `docs/development/WORKFLOW.md`. A live paid provider, new account/global settings, another OS/installer, H029 disconnect, and H030 tray are not introduced in this task. A short replay is not prolonged-load or all-provider support evidence.
