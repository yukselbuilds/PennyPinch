## Scope and preserved contracts

- The existing atomic PreferenceStore stores an `operating` record alongside language/theme. It contains `close_to_tray:true`, `retention_days:30` (7/30/90), and `protected_tools:[]` (up to 32 unique, sorted ASCII tool names, 1–96 characters, excluding spaces and limited to letters/digits/`_-. :/`). When reading a legacy schema1 language/theme record, use default operating values. Reading does not change the disk. A legacy save call does not reset operating. Preserve revision/fingerprint CAS and safe atomic replacement. Do not overwrite a malformed record with defaults.
- The preference to keep running in the tray applies on the next X. If it is off, X asks for explicit quit confirmation and does not silently stop the engine. Pause/retrieval/stream and H030 ExitGate contracts do not change. Full quit is the same for either preference.
- Retention applies only to the app's local measurement metadata. After a 7/30/90 choice is saved, the same cutoff is used in the next collection/query and the same retention is returned in the response. A shorter period may permanently remove older measurements, which the UI explains before saving. Extending retention does not restore deleted records. CCR7200s and the raw-content policy do not change. No secure forensic deletion is claimed.
- Protected tools are added to the existing pinned 0.41.0 `HEADROOM_PROTECT_TOOL_RESULTS` path. Default coding/cache protections remain. The change takes effect on the next manual engine start. There is no automatic restart or interruption of active streams. The UI compares the saved list with the list in the actually verified engine generation and shows pending changes. It affects all connection/model/main-agent/subagent traffic passing through this shared engine. No guarantee is made for traffic outside the proxy. There is no protection guarantee for calls that do not report a tool name. `numeric_report` is not made a production default.
- The engine helper passes only the verified tool list through its own safe environment and compares it with the live health exclude set and ready protocol. Stats-on/beacon-off and coding/cache/TTL/memory/learn/output/model-router pins do not change. If the engine is not ready, its effective settings are unknown/inactive. A saved value is not shown as applied. Vendor sources are not modified.
- Windows startup is a separate observation of the actual OS registration. PreferenceStore does not keep a second desired copy. Do not write HKCU Run until the user clicks. Manage only the fixed Headroom value name and the executable command verified by the backend. Do not claim or delete another value or target. Serialize operations and preserve conflicts with the expected fingerprint and a reread. The UI distinguishes registered/disabled/conflict/unavailable. OS policy/TaskManager decisions and actual login success are not considered proven. Startup opens only the window and does not start the engine automatically. Tests use the same Windows API in a project-UUID isolated test registry key. The real Run registration remains unchanged.
