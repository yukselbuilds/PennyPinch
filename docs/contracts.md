# Local Application Contracts

**Date:** Baseline decision, 19 October 2026; H012 acceptance, 15 November. **Status:** The architecture and interface contract matches the current source. The technical foundation is in [runtime decision 002](decisions/002-runtime.md); compatibility entries are in [compatibility/clients.json](../compatibility/clients.json). Source mappings and support boundaries for the 39 commands in section 8 are recorded in the [H012 acceptance](proofs/architecture-acceptance.md).

## 1. Shared responses and boundaries

Tauri responses carry schema_version=1. This differs from the helper's stdio JSONL protocol_version=1. Requests and responses correlate by the same opaque request_id; engine control also validates generation and revision boundaries. Input is not one universal DTO: a command accepts either direct arguments or a strict family-specific request. For example, manage_account and manage_sessions requests contain a schema field; manage_updates and export_report requests do not. Do not add absent fields; preserve the deny_unknown_fields contract. An unexpected helper version or message type must not produce ready or success.

For families using the shared runtime/state envelope, errors have the form {schema_version, request_id, status:"error", error:{code, retryable, message_key, diagnostic_id}}; diagnostic_id is null when absent. This is not the error type for every RPC: H050/H051 use a fixed-code-or-null error field, while update/export use their own strict responses. Each family is decoded by its Rust DTO and matching TS decoder; the renderer must not infer success from retryability or free-form error text. RuntimeManager codes are limited to validation_failed, unsupported_protocol, environment_blocked, busy, port_conflict, engine_not_ready, ownership_lost, timeout, cleanup_failed, and config_conflict; other families define their own allowlists. Raw exceptions, subprocess stdout/stderr, auth data, and engine response bodies are not passed to the UI; only explicitly defined narrow fields are shown. Unknown enums or versions do not count as success or compatibility.

UI commands are narrow and typed. They do not accept a runtime executable path, arbitrary arguments, upstream URL, shell code, random port, or file contents to read. File selection uses only the validated backend picker in the relevant client-location flow. At startup, a single window and manager own the same runtime generation.

**Default model/agent scope (20 October 2026):** A connection covers all supported models and main/subagents that use the same verified route; users do not configure each model or subagent separately. Model, effort, and agent count remain unchanged. A separate provider, protocol, process, or cloud route requires its own plan and evidence. Coverage, role attribution, and actual optimization results are separate fields: a request with an unknown agent identity may still be optimized on a supported route, but the missing identity cannot justify a claim that all subagents are verified. This decision does not upgrade not_tested or unknown records in the current compatibility catalog.

Current source distinction: [OpenAI's subagent documentation](https://learn.chatgpt.com/docs/agent-configuration/subagents) explains that model/effort can be customized in a custom-agent file, while other session settings such as model_provider do not override the parent config. The [Headroom proxy documentation](https://docs.headroomlabs.ai/docs/proxy) describes protocol/endpoint and auth routes separately. These are design inputs, not substitutes for local validation against pinned 0.41.0, an installed client, or native subagents.

| Command family | Input | Result / implementation gate |
| --- | --- | --- |
| Runtime snapshot | None | State DTO below; read-only. |
| Start engine | None; settings come from backend state | Idempotent start request plus current snapshot; H014. ready requires real evidence. |
| Stop engine | Expected runtime generation | Bounded shutdown after reviewing active traffic/connection effects; H029/H030 semantics. |
| Pause/resume compression | Expected generation, revision, and target | H028 set_optimization; snapshot after a real control acknowledgement. Not a proxy restart or config rollback. |

These are command families. H013 opens only the implemented narrow snapshot/health boundary. Later families' names and request/response types are fixed in their implementation slices; an empty stub does not return success.

## 2. Separate state machines

**Engine:** unavailable | stopped | starting | ready | stopping | failed | unknown. A snapshot carries at least schema_version, snapshot_id, observed_at_utc, runtime_generation, engine_version, state, and a fixed error code. Use unknown when there is no observation or it is stale; do not infer ready or stopped. PID/loopback address are internal diagnostic metadata and do not let the UI choose its own management target. A late response from a previous generation cannot mark the new generation ready.

**Compression (H028, 5 November 2026):** unavailable | enabled | paused | unknown; revision is a JS-safe number when control state is known and otherwise null. If a ready engine's control state cannot be read, use unknown; for other engine states use unavailable. pausing is a renderer operation in progress, not an acknowledged engine state. capabilities.pause authorizes the pause/resume action for the current state. New pause is disabled without safe replay evidence; resume remains available. active_stream_count stays null; request counts from private control HTTP and ingress TCP are not stream counts.

**Discovery:** not_scanned | detected | not_detected | error; client version is null when unknown. not_detected does not mean protocol incompatibility.

H016 Applications has a separate get_discovery_snapshot / scan_discovery command family; the discovery placeholder in H014's general runtime snapshot is not used on that screen. With schema1/UUID request correlation and increasing scan_generation, the initial state is not_scanned and a bounded scan result is partial. installations contains only detected candidates; each has an opaque UUID, client/surface, validated version or null, fixed source/location label, and connection_status:not_verified. Raw installation paths stay in the backend. A client absent from the list was not found only within the scanned scope; that does not mean it is unsupported or connected. Discovery does not read or change config/auth/chat data. The current Codex adapter may run a narrow --version query for a trusted real executable identified by publisher signature/file identity; the environment is cleaned, the user profile is not inherited, and time/output are bounded. Unknown programs and wrappers are not executed for discovery. See the [source boundary](../src-tauri/src/integrations/codex_binary.rs) and [current Codex evidence](proofs/codex-current.md). Fixed error allowlist: validation_failed | busy | environment_blocked; details are in docs/proofs/discovery-backend.md.

**Connection:** disconnected | planned | applying | needs_restart | verifying | verified | config_conflict | failed. verified records which surface/version/auth/protocol/transport was verified and when. Stopping the runtime does not erase config ownership; the UI shows the connection record separately from live route state.

**H017 read-only preview (21 October 2026):** preview_connection_plan({request}) accepts only schema_version, opaque request_id/installation_id, positive JS-safe scan_generation, and scope:"user_config" in a deny-unknown-fields schema1 request. The renderer does not supply config path, model, auth, provider URL, or port. Installation comes from current discovery state and address from the fresh H040 accessor; a stopped engine may still have a bound ingress. No plan is returned if discovery, endpoint, or file fingerprints differ between the initial and final checks. Only one file read runs at a time; at most 64 redacted plan leases are held in memory for five minutes.

The success envelope is {schema_version,request_id,status:"preview",plan}. The plan's inner status:"preview"|"blocked" identifies draft blockers; it is not connection verification. The plan carries installation/generation/scope, expiring plan UUID, source/presence, secret-free fingerprint, loopback-only target and required endpoint field, preservation of model/provider/auth/reasoning/agent count, config declaration states, hook/shell summary, new-process/session requirement, and fixed blockers. runtime_effective:"unknown"; a config declaration does not prove the value used by an open client. Missing config indicates a need for a new file but does not create a file or directory. An unknown version/surface or route may yield a blocked parseable draft; malformed input returns an error. Other provider/cloud routes and all open sessions are not included automatically.

config_fingerprint is not a raw file SHA: it binds a versioned domain, client/scope/source/presence, length-framed content SHA-256, backend target identity, and Windows file identity. The path itself is not exposed in DTOs or logs. The same bytes in a different file object, or a JSON-to-JSONC slot change, counts as drift. H018 must recheck this binding and the lease lifetime; H017 does not open a write/rollback command.

If the Windows OpenCode plan needs a local retrieval bridge, it carries opencode_retrieval:"install_local_bridge". V1 uses mcp.headroom; V2 uses mcp.servers.headroom. An existing Headroom entry or user settings that cannot be merged safely is shown as opencode_retrieval:"conflict" with a retrieval_mcp_conflict blocker. The bridge command is prepared only inside the native lease. Apply uses the displayed plan and revalidates runtime and user files before writing. JSONC processing writes eligible routes and the MCP entry together. Receipts track ownership of created mcp and V2 servers containers separately.

V2 plans and native receipts carry opencode_schema:"v2"; absence of the field denotes the legacy V1 schema. The wire client and shared ownership slot remain opencode_v1. V2 endpoints are under providers.<alias>.settings.baseURL. The TS decoder accepts the label only for OpenCode; applying requires the local bridge. The V2 bridge definition carries disabled:false, codemode:false, protocol:"legacy", and a bounded timeout. User permissions are not enabled; retrieval denial produces a retrieval_unavailable blocker. A wrong schema or conflicting bridge/endpoint byte hash stops atomic write and rollback. [V1/V2 decision](decisions/009-opencode-provider-routes.md)

The error envelope uses the shared shape; its narrow codes are validation_failed, unsupported_scope, stale_selection, not_found, endpoint_unavailable, config_unavailable, config_unsafe, config_too_large, config_conflict, config_invalid, and busy. diagnostic_id:null; retryability and connection.<code> message key are fixed. The strict TS decoder rejects extra/private fields, incorrect request/installation/client/generation correlation, source/presence/field/URL inconsistencies, false declarations for missing config, unrenderable dates, and flags that violate preservation. Client model/auth files and chat databases are not executed or modified. [Evidence and limits](proofs/connection-plan.md).

## 3. Runtime control

The fixed payload path comes from the Rust bundle resolver. The backend creates app-state/workspace/config paths. Helper input/output uses a bounded JSON-lines protocol; protocol version, message type, and source process handle are validated. Raw engine logs are not protocol messages.

Startup order is manifest/guard check → app-owned helper → app-owned engine/listener → pinned readiness → publish snapshot. H006's packaged runtime tree is the startup baseline and reference payload; H014 separately validates the production Tauri binding. A foreign listener, wrong version, timeout, and helper exit have distinct error codes. A second click during startup does not create another engine.

On EOF/normal exit, control-channel closure starts a bounded stop; the outcome reports timeout/fallback. No other PID/port is killed. A new ready generation is not declared until the previous engine's port is free. Abrupt exit/Job Object behavior is tested separately from normal shutdown.

The opaque cache-marker shim proven in H007 was carried to the production Python overlay/bootstrap with the same hash in H014-a; the H006 package tree was not changed. The controller checks fixed manifest/profile and payload hashes; the engine runs the 0.41.0/full prefix_tracker.py source guard during bootstrap. A failed guard prevents readiness. Rust/UI engine binding was separately accepted on the current host in H014-b/c; installer work is H037. The adapter may remove only the marker Headroom added to an opaque block; it must not change explicit client markers or recognized blocks. A new upstream version/hash requires new proof; no silent patching. [H014-a evidence](proofs/desktop-runtime.md), [H014 acceptance](reviews/H014.md).

**H040 stable ingress contract (21 October 2026):** get_ingress_snapshot(request_id) is a separate schema1 response and does not change fields in the existing runtime snapshot. endpoint carries only state, persistent UUID, app-selected 127.0.0.1/port, and a fixed error code; backend carries state, temporary engine generation, and a fixed error code. Nullable active_connection_count is a TCP connection count, not HTTP request or SSE stream count. The UI cannot supply a URL, PID, executable, or target port to this command. H017's planner uses the same runtime manager's fresh ready_stable_endpoint() accessor; existing Start/Stop commands use the manager for ingress lifecycle.

Endpoint observation and engine health update separately; an expired observation yields unknown/timeout and a nullable counter. The endpoint identity/address remains stable across engine restarts; each TCP connection is pinned to one backend generation. If the recorded port is occupied, another address is not selected. Client payload is not forwarded until the backend socket's exact established peer PID is validated. Validation includes a held process handle, Job Object membership, parent chain, and generation, not PID alone. Windows may have additional owned console processes, so security does not depend on counting exactly three processes.

Stop order is remove new routes → graceful engine stop → bounded TCP drain → verify owned cleanup. Forced cancellation is not graceful success; completed cleanup and uncertain cleanup are distinct. Direct upstream fail-open is disabled; a disconnected POST/SSE request is not resent to another backend. Gateway/OAuth, CCR/pause, live clients, and model support are not proven by this transport contract. The port is released when the app fully exits; tray/background behavior and config rollback are separately gated by H018/H029/H030/H034. [Failure matrix](validation/ingress-failure-matrix.md), [decision](decisions/003-connection-ingress.md), [local evidence](proofs/connection-ingress.md).

H028 set_optimization(request_id, expected_generation, expected_revision, enabled) accepts only typed targets. The renderer cannot send a port, nonce, URL, PID, or private control body. The path is Rust → actor → held process/Job/generation plus exact connected-peer validation → one private POST → correlated acknowledgement → snapshot. Engine health may be ready while compression control remains unknown; failed control does not kill the engine. No automatic command retry or switch to another engine occurs. A failed acknowledgement/read never produces optimistic success; recovery uses a fresh read.

The ephemeral nonce exists only in private bootstrap/ready state and native memory; it is excluded from DTO/state/log/export. The same engine/endpoint/CCR store is retained, with the HTTP decision fixed at request start and the WS decision fixed at a frame boundary. Pause is rejected if source/payload/capacity or executor timeout undermines confidence; paused replay does not silently fall back to the raw prefix. Pinned vendor files are not modified. [Decision 016](decisions/016-safe-pause.md), [local H011/H028 acceptance](proofs/safe-pause.md).

## 4. Config ownership and undo

The plan is kept server-side; auth/secret values and the full config body are not returned to the UI. It is bound to the current content fingerprint, selected surface/scope, and ownership information for only the fields to be changed. Drift at apply time requires a new plan.

JSONC comments and unrelated TOML/JSON fields are preserved. The H018 Windows backend uses capability-gated KTM/TxF: config and the content-free ownership record are published in one transaction on the same local fixed NTFS volume. Identity/content/root and lease are rechecked before commit; unsupported filesystems, reparse points, hardlinks, EFS, and readonly files are rejected. There is no weaker rename fallback. TxF maintenance/future-support risk is in [decision 005](decisions/005-config-transaction.md). An uncertain commit response is not treated as unchanged or successful; ownership must be read again, with no automatic write retry.

Undo removes only the endpoint field still written by the app. A later user change to that endpoint remains a conflict; unrelated changes and the new file identity from a normal atomic save are preserved. The whole config is neither backed up nor restored; created files and containers with user content are not deleted. If the same endpoint already belonged to the user, no new ownership or Undo permission is created.

Three commands share one manager/operation lock: apply_connection_plan, undo_connection, and get_connection_ownership. Requests are limited to schema1/request UUID. Apply carries plan UUID plus expected config fingerprint; Undo carries client enum, owner UUID, expected revision, and record fingerprint; snapshot carries only client enum. The renderer neither sends nor receives a free-form path/URL/config/auth value. Wire client enums are codex | claude_code | opencode_v1; discovery opencode is explicitly mapped in the UI. Responses use applied | unchanged | released | snapshot and nullable ownership metadata; the strict TS decoder validates request/client/operation/route/revision correlation. Only fixed error codes and message keys are displayed; raw errors are not shown.

V1/V2 share the same config resolver, transaction, and ownership record. Optional opencode_schema preserves decoding of old receipts. Created V2 ancestors are undone only if empty and containing no user data. Preservation of model, auth, permissions, and other user settings applies to this schema distinction as well.

On opening Graphite connection management, a passive ownership snapshot is read; Preview is a separate action. Apply requires a valid plan and a current successful ownership read. Repeated writes/Close/Escape/selection are blocked while a mutation is pending. Existing ownership can still be undone if an installation is not found. After app restart, the record is found; an old expiring plan does not become valid again. A saved route is not proof of a live connection; Headroom/engine must be running and the client must use the setting in a new process. App exit does not automatically undo the route.

The current model, reasoning, auth method, agent count, and permission settings are not changed. A process-scoped fixture profile is not a production connection plan. The UI does not claim success for unsupported or managed config scopes. If a restart is required, its actual effect appears in the plan and connection state.

## 5. Content-free metrics

A normalized record carries source/provenance, runtime generation, unique event identity, UTC time, allowed client/model labels, nullable session/project/agent relationships, measurement basis, and measurement state. A model name alone is not agent identity. Use a trusted local mapping rather than a user path or arbitrary header/tag association.

Before/after values B/A are comparable only on the same tokenizer basis; if either is absent, the pair remains partial. Both are nonnegative, but S=B-A may be negative. Provider usage, local token estimates, wire reduction, novel gains, cache/uncached breakdown, tool schema, and estimated cost are separate fields/bases.

Each pair also declares which components it covers; a source measuring messages alone is not the total for all input/system/tool schema. A separate savings layer is not added to the primary share without a non-overlapping comparable basis. Output savings are not mixed into the input ratio.

The primary query result:

- Period start/end and timezone; source time and last update.
- before_tokens, after_tokens, saved_tokens, and saved_percent for valid pairs on the same basis. Percentage is 100×saved_tokens/before_tokens only when the base is positive.
- Count of measurable requests, known total/observed traffic count, and partial/missing-interval state. If the total is unknown, do not invent a coverage percentage.
- totals.status = measured | no_comparable_events | mixed_bases | counter_overflow; a real zero is valid. Different tokenizer bases are not combined into one definite total.

H014's shared runtime snapshot has a metrics field with waiting status and null counters. H024/H025 period totals use PeriodTotals and the corresponding strict TS decoder. Per-request projections use MetricSummary. The source collector's collection.status is shown separately.

Duplicate events are not ingested. A snapshot delta and event total do not contribute twice to the same event. Restarts/counter resets are separated by runtime generation. If the polling buffer is exceeded, a gap is recorded. A ledger containing only events with savings is not the denominator for all traffic.

The UI, chart, and JSON/CSV use the same query result; rounding occurs only for display. Token increases are not hidden. TR/EN formatting does not change numeric data or period. If cost estimates are shown, price date/source and cache basis are displayed separately; the primary token ratio is not presented as a bill or subscription-quota reduction.

Raw logs outside the allowlist, request_messages, compressed_messages, auth, URL query/header, and free-form tags do not enter this layer. Details/fingerprints are in the [pinned metrics source note](research/metrics-0.41.0.md).

### H023 normalization API

The pure API in src-tauri/src/metrics/normalize.rs produces schema1. H023 does not start UI or polling; H024 adds persistent storage/query and the collector's record ingress, while H025 connects live owned-source collection and the view. H024 alone does not start engine polling.

- normalize processes the trusted collector's Observation array. Reading carries nullable tokens, local/provider/unknown kind, versioned counting method plus tokenizer identity, and component. A model name or tokenizer label alone is not evidence of comparability. Derive amount and percentage for before/after only when they share the same evidenced basis; percentage requires a positive base.
- main_metric_eligible is true only for a dated, provenance-verified Headroom message/whole-input pair. Percentage is null even when a zero-base amount is known. RTK/tool-schema/novel/cache/output are separate measurements; provider usage fields are not added to the main pair. Different tokenizers or components cannot form one total.
- origin_id is a SHA-256 key of runtime generation plus request provenance. event_id also includes the fixed optimizer/component slot. Separate layers for one request may be separate events: request count is not event-row count. The primary metric is computed only from eligible rows sharing the same component/basis. Overlapping repeated contributions conflict because message/whole-input slots are shared.
- observed_via identifies observation channels only; without a trusted proxy-origin mapping, MCP contributes nothing to the primary total. Mappings in content/tags are not trusted. Canonical Observation is not a renderer/raw-engine input contract; the native collector verifies provenance/basis. Identical payloads merge; conflicting amounts make amount/percentage and uncertain basis/time unknown. Generations remain distinct. Upsert/retention between polls use the same keys in H024.
- project_headroom_041 is a bounded JSON metadata adapter: prefer recent_requests, falling back to request_logs; never count both lists. Raw payload, ID, auth, model/agent/project inference, free-form tags, and lifetime values are not returned. If the basis/component of an old count is unknown, preserve the raw before/after observation; do not infer saved/percentage or provider-usage provenance.
- reported_request_count, unidentified_rows, rolling_window, aggregate_only, and complete_traffic=false keep source coverage explicit. Aggregate counters are not added to or differenced from event totals; reset/restart does not create savings. Unknown total is not converted to zero; old lifetime data seen in samples is not carried into current traffic. H024 stores source warnings and retention; do not claim complete traffic until actual polling/gap coverage is verified with the H025 collector.

Boundaries and decision: [010](decisions/010-metrics-normalization.md). Fixed NormalizeError values contain no payload. No new dependency is added; the existing time crate's parsing feature is used.

### H024 storage and query API

- Crate-internal MetricsStore.ingest_projection records H023 EngineProjection metadata with event_id upsert in a transaction. There is no renderer write IPC that accepts events/import SQL or a file path. The first monitoring-session/first-seen time does not change during replay; the shared normalizer merge absorbs conflicts. Non-conflicting event_id values are revalidated from origin plus optimizer/component slot.
- get_metrics_summary({request:{schema_version:1,request_id:<canonical non-nil UUID>,period:"session"|"today"|"seven_days"}}) queries only the local store; it does not call the engine/model. The Tauri command moves blocking DB work off the UI thread. It returns status:"ok" with data, or a fixed-code status:"error"; the error response contains no input/payload/local path.
- data: monitoring_session_id, period, UTC from_utc/to_utc, retention_days:30, totals, coverage. A session is this Headroom process's monitoring session, not a Codex/Claude account or chat. Today and seven_days resolve against the local calendar at query time. Retained records whose time cannot be placed are not counted as occurring in the selected period; unplaced_events/excluded show only that uncertainty.
- totals.status: measured | no_comparable_events | mixed_bases | counter_overflow; nullable before/after/saved/percentage are weighted only on the same basis. Groups with different tokenizer/counter kind/component are not combined. At most 64 groups of detail are returned with omitted_basis_groups; omitted groups are not combined into the main percentage. Provider/cache/output/RTK are not added to main input.
- coverage: event and distinct-origin counts, unplaced time, rolling/aggregate/unidentified-source warnings; complete_traffic=false. These numbers are not all traffic or user-turn counts. Ingest counts and lifetime snapshot totals are not added to period savings.
- Startup and empty query do not create files. Debug root is repository work/app-state/metrics; release root is the app's local-data metrics directory. Limits are 30 days, 100,000 events, 128 MiB DB, and 4,096 bytes/event; schema/app-id, reparse/hardlink, busy, and transaction-rollback protections apply. See [012](decisions/012-metrics-store.md).

### H025 live Overview API

- get_overview_snapshot({request:{schema_version:1,request_id:<canonical non-nil UUID>,period:"session"|"today"|"seven_days"}}) is a local read; it does not start HTTP/model traffic. It returns the same fixed H024 error DTO or status:"ok", observed_at_utc, data, collection.
- data adds last_event_utc and series:[{at_utc,through_utc?,totals}] to the H024 period contract. When the main total is measured, actual hourly/local-day measurements are represented by up to 64 chart points. If the limit is exceeded, the oldest measured days are merged as needed. at_utc is the start; when present, through_utc is the start of the last measured day in the group. Point counters and comparable-event counts match the period totals. Intervals with no data are omitted. The UI uses only validated display fields.
- collection: status:waiting|recording|stopped|interrupted|unavailable, interval_seconds:5, nullable last_capture_utc, current runtime's 32-hex runtime_generation, nullable fixed last_error, sampling_interrupted_since_start. H023 events' hyphenated canonical generation is the same UUID value; monitoring-session ID remains separate. Sticky interruption and rolling coverage do not prove all traffic.
- While the app is running, the collector reads only fixed /stats?cached=1 metadata from the owned ready source through the runtime actor, even when Overview is not visible. Peer/lease/generation are checked; limits are 2 MiB/1.5 s. No content is retained beyond the H023 allowlist and H024 upsert. Shutdown order is collector → runtime. Pinned 0.41.0 does not make an unknown basis comparable.
- When the period changes, the UI discards old responses; on an error in the same period it shows the old view as stale with time/reason. A connection record does not mean an open client, account, chat, or model traffic. Window-specific 100/125/150 zoom uses Tauri main-window capability; it does not write a saved preference or OS DPI. [Plan 013](decisions/013-live-overview.md), [acceptance](proofs/live-overview.md).

### H026 attribution and role coverage

- Schema1 Observation/NormalizedEvent adds attribution defaulting to unknown. Older payloads may omit the field; event_id and first monitoring-session time are preserved. The current reader can read older records; SQL schema/retention/file protections do not change. Metadata enrichment and absorbing metadata conflicts are distinct from token conflicts.
- Pinned RawRow exposes only a limited model/provider label. The engine's heuristic agent summary, tags/headers/raw attribution/client/agent/role fields are not witnesses. A native route witness is bound to the same request/runtime through origin_id; upstream and agent/parent identities are opaque 64-hex values. Raw upstream/agent IDs/URLs are not written. The current pinned adapter does not produce this witness; this is a constructor/mapping fixture contract. A model name is not identity or role.
- data.attribution: scope:"observed_requests", coverage:{requests,events,model_observed,client_verified,agent_verified,conflicts}, client_status/agent_status:unknown|partial|verified, groups, omitted_groups. Requests are distinct opaque origins, not the same count as events or billable calls. Coverage includes only selected-period records that are stored; uncorrelated sources are not treated as the same physical call.
- Group: opaque group_id, nullable model/provider/client/upstream_id/agent, conflicted, is_other, the same coverage counters, and H024 totals. agent:{id,parent_id,role:unknown|main|subagent}; client codex|claude_code|opencode. It does not merge two agents or different upstreams with the same model. Without a native witness, role/client is unknown; this is not an optimization filter.
- At most 64 group rows are returned; overflow is represented in the final visible Other row. Main/group totals use the same event set and current counter basis. The TS decoder validates count/state/identity/role/label/Other and amount conservation. The UI shows only a short hash discriminator; a model/provider label is not proof of a real account/auth or all subagents being covered. [Plan 014](decisions/014-attribution.md), [acceptance](proofs/attribution.md).

### H027 content-free activity API

- get_activity_snapshot({request:{schema_version:1,request_id:<canonical non-nil UUID>,period,filter}}) and get_activity_detail({request:{schema_version:1,request_id,period,origin_id:<64hex>}}) read local metadata only. They use the same select_period, monitoring session/local calendar/30-day retention, and collector lock as Overview; they do not start the engine or model. not_found is added to the fixed H024 error codes for detail. No renderer write/import/path/SQL or file-export API is added.
- Filters: client:any|unknown|codex|claude_code|opencode; model:{kind:any|unknown}|{kind:exact,value:<safe label>}; outcome:any|unknown|no_error_reported|error_reported; measurement:any|measured|unmeasurable|conflict. Model filters/labels are limited to 128 safe ASCII characters; URL, absolute personal paths, and known key prefixes are rejected. Apply filters to all selected origins, then return the newest 100 records in time order; unknown time sorts last and equal times are stable by opaque identity.
- List returns observed_at_utc,data,collection. Data: period boundaries, monitoring UUID, retention/coverage, matched_requests,shown_requests,limit:100,has_more,unplaced_requests,rows. Unplaced is time uncertainty; it is not proof of missing attribution or that an event occurred in the selected period. Records are grouped by opaque origin; they are not billable/provider-call or all-traffic counts. Attribution preserves H026's evidence boundary; client/role is not inferred from model.
- Row: opaque origin_id, nullable UTC time, sanitized identity, metadata, compact H024 weighted totals, measurement, event count, and observed optimizer layers. RTK/cache/output/tool schema are not added to main savings. Detail returns period,row,measurements,omitted_measurements; at most 32 measurements are shown, while totals use all events. A measurement includes counter/source/component/state/eligibility and numeric provider usage; it uses opaque basis_id instead of a tokenizer label. Raw NormalizedEvent or engine JSON is not sent.
- Schema1 Observation/event adds metadata defaulting to unknown; older payloads remain readable. Durations are finite 0..86,400,000 ms and transform count is 0..128; zero is not missing. Metadata enrichment/absorbing conflict is distinct from token and attribution conflicts. Conflict clears metadata without changing measured tokens. SQL schema and file protections remain unchanged.
- Pinned 0.41.0 primary recent_requests is supplemented, when present, by secondary request_logs metadata with the same raw request_id plus timestamp and non-conflicting model; the second list is not counted again. total_latency_ms, optimization_latency_ms, nullable source cache flag, and transform count only are read. Error value is discarded as IgnoredAny during deserialization; missing/null/non-null map to unknown/no_error_reported/error_reported. Error body, transform name, tag, content, and command output are not stored. First-token duration is absent from this source; it is not filled from a random TTFT/tag field. Null error means no error was reported, not success; cache flag is not proof of a provider discount.
- While Activity is visible, the local query refreshes every 5 seconds. List and detail channels preserve one query/last-scope rule; old responses are not shown after period/filter/selection changes. A query error in the same scope keeps the previous view with an explicit stale label. File/CSV export is H033; this task validates only the content-free serializable DTO boundary. [Plan 015](decisions/015-activity.md), [acceptance](proofs/activity.md).

## 6. Compatibility catalog

Each entry is defined by client version range, surface, auth method, protocol/transport, capability, and evidence reference. The catalog is in [compatibility/clients.json](../compatibility/clients.json). States are not_tested | unknown | local_fixture_partial | local_fixture_pass | live_verified | unsupported | environment_blocked; a reason and measurement date are required. Use unknown when the attempted outcome's semantics cannot be classified; use not_tested when that combination has never been tested. An OS/policy block is environment_blocked, not a compatibility claim. Partial evidence must state separately which sub-behavior passed and what remains unknown. A local PASS belongs only to that version/surface/auth/protocol row and does not automatically become live support. Use unsupported only with concrete incompatibility evidence.

The catalog keeps H006-a/H007 and H009-a/H010-a fixture coverage, H020/H021 local product paths, H008's Windows 10 ChatGPT CLI/Desktop live evidence bounded by version/surface, and H048 controlled macOS Desktop traffic in separate records. Codex ChatGPT/API/desktop/subagent, Claude bare API/OAuth/extension, and OpenCode V1/V2/TUI are not interchangeable acceptance combinations. A new live record for another version/surface does not invalidate an older not_tested row, and it does not upgrade that older combination. When a version/transport changes, only related evidence becomes stale; an old PASS does not transfer to a new combination. Account reading and chat metadata capability are separate from inference/protocol support; H050/H051 do not upgrade a compression record.

Layer coverage is separate too: a Headroom protocol route is not terminal filter/hook coverage. H043 did not establish an accepted RTK-OSS 1.1.0 filter path, so the catalog does not claim an installed/working RTK integration; H044 awaits new evidence. Shell-hook success is not added to PowerShell/Read/Grep/Desktop coverage or Headroom's token counter.

### H050 — Account envelope and official sign-in

[manage_account](../src-tauri/src/integrations/accounts.rs) request carries schema/request identity, read | start_login | active_login | poll_login | cancel_login, nullable installation/scan/flow IDs, and explicit confirm_profile_change. Read/start bind to a fresh discovery selection; poll/cancel bind to an opaque flow ID. The webview does not send auth, provider URL, file path, or argv. The response combines schema/request/status with account, flow, and error fields; on error account/flow are null and error is an allowed fixed code. [accounts.ts](../src/lib/accounts.ts) validates exact keys and installation/client/surface/flow correlation.

Account present | absent | unknown describes a local credential record; remote_verified:false makes clear that the remote account/subscription has not been verified. Codex uses a bounded official status command. Claude 2.1.158 remains unknown with read_not_passive because its status command is not passive; for OpenCode 1.19.3, the app reads safe fixed-schema local provider metadata rather than invoking auth list. Raw output, email, or secret is not copied to DTO/log/state. Official sign-in opens only after an explicit user action and shows the profile/method that may change; cancel stops only the owned CLI root, does not undo auth, and does not close the browser. [Decision and acceptance boundary](decisions/030-account-connections.md).

### H051 — Session metadata and opening the client center

[manage_sessions](../src-tauri/src/integrations/sessions.rs) request carries schema/request identity, read | open_codex_center, nullable snapshot_id, and confirm_open. Response carries schema/request/status, nullable snapshot, and nullable fixed error code; a launched response does not return data/message history. [sessions.ts](../src/lib/sessions.ts) validates exact fields, unique opaque keys, three client scopes, and a limit of 256 rows. Scope is current_cli_environment; this does not mean all Desktop/CLI sessions outside that profile were found.

The Windows 10 adapter connects metadata-only to the existing trusted Codex 0.167.0-alpha.4.1 endpoint after peer PID/SID/signature/version checks. Apart from the narrow version-query exception above, it does not start a server/session or change settings/auth. Titles, previews, or message/turn history do not enter DTO/state; a project is a short label and session/parent are opaque hash identities. Model/provider/reasoning are observations, not selections or a model allowlist. Two rows with the same model are not assumed to be the same session/role. Loaded/running/waiting/recorded/ended/unknown witnesses remain separate; a disconnected server does not imply every session ended.

traffic_assignment:"unverified" is preserved at both snapshot and row level; session savings are not inferred from similar model/account/project labels. The open action uses a fresh single-use snapshot/confirmation to start the same trusted server's official center with fixed arguments; it does not send resume for a particular session or override model/reasoning. Normal Headroom exit does not close the opened official center. Live Claude/OpenCode metadata and other versions/profiles/OSes do not follow from this Windows local acceptance. [Decision and real native evidence](decisions/031-session-metadata.md).

### H042 / H032 — Update and export envelopes

[manage_updates](../src-tauri/src/desktop/update_flow.rs) request contains request_id and a deny-unknown-fields action; actions are snapshot, check with channel, download/apply with candidate ID, and rollback with recovery ID. The request has no schema field; the response uses schema1/request correlation and nullable fixed Failure code. Renderer does not supply download URL, package path, key, or command. Apply is not allowed until signature/hash/app-target/engine pin, fresh candidate, safe stop, and owned installed version are validated. [Trust contract](decisions/028-update-trust.md); a local signed Windows 10 fixture is not a production release.

[export_report](../src-tauri/src/export/report.rs) request contains request_id, report kind/language, and nullable snapshot_request_id; the request has no schema field. The report is generated from a selected aggregate projection held in the backend's bounded cache and written through the native file picker. Renderer sends no data/body/path; cancel or a snapshot no longer in cache is not success. Export does not send remote report/telemetry; H052–H054 remain deferred.
